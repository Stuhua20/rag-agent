# LangGraph统一聊天与表格自动分析实施记录

> 历史归档：2026-10-19已按用户要求移除表格分析Agent及自动调度/聊天附件代码。本文记录历史设计与验收，不代表当前功能；参见[移除记录](表格分析Agent移除记录-2026-10-19.md)。

实施日期：2026-10-18。依据：[自动调度与数据发现改造方案](LangGraph表格分析Agent自动调度与数据发现改造方案.md)。用户已明确授权实施。

## 1. 本次交付

聊天统一使用自动入口：直接提问、上传Excel/CSV或粘贴表格，系统识别任务、寻找允许范围内的数据，在必要时澄清后执行。无需先选Agent、Sheet或手动建索引。知识问答与表格计算保留独立模块，由统一LangGraph主图组合。

| 数据入口 | 行为 |
|---|---|
| 已有文件库Excel/CSV | 在当前文档范围内发现候选；原始文件可用即可准备结构化数据，不要求Embedding成功 |
| 聊天附件Excel/CSV | 仅归属于当前会话，不运行Embedding；可明确另存文件库 |
| 粘贴数据 | 支持围栏CSV、围栏/独立矩形Markdown表格；保留原文、标识符及来源位置 |
| 仅发附件 | 给字段、记录数、日期范围、缺失/异常、重复候选等概览及可开展分析建议 |

支持多指标统计、条件筛选、最多两列分组、排序/Top N、占比、同表四则派生、自然月环比；数字由Decimal计算与程序渲染。支持“统计+独立资料说明”的组合问题。每个目标都核对完成状态，不以一个成功目标掩盖其余目标。

连续追问保存已确认的数据、指标、筛选及版本。未修改的筛选由程序补入计划，不单纯依赖模型记忆。问知识概念不会清空上次分析。修改文件或数据版本会重新确认，修改文档范围立即约束新运行及历史源行访问。

## 2. 代码位置与执行链路

```text
backend/app/agents/
  unified_chat/
    contracts.py       # 任务、目标覆盖、候选和澄清契约
    planner.py         # 任务理解、独立覆盖检查、逐候选评估
    state.py           # 主图状态
    graph.py           # 统一LangGraph
    nodes.py           # 发现、准备、子图调用、合成和一次提交
    runtime.py         # 请求校验、占用、预算、SSE、会话保存
  knowledge_qa/        # 知识问答子图，保留独立入口
  table_analysis/      # 声明式计划和可靠计算子图，保留独立入口

backend/app/services/
  chat_dispatcher.py
  source_catalog_service.py
  conversation_attachment_service.py
  inline_table_service.py
  table_discovery_service.py
  analysis_session_service.py
  table_dataset_store.py
  table_result_service.py
backend/app/routers/conversation_attachments.py
prompts/unified_chat/{task_understanding,task_coverage,source_selection}.md
frontend/src/components/{ChatAttachmentInput,DataSourceClarification,AnalysisContextSummary}.tsx
backend/tests/test_unified_chat.py
```

主图顺序：理解任务及覆盖检查 → 自动发现/澄清 → 准备完整表格 → 表格子图及/或知识问答子图 → 核对所有目标 → 保存一次回答。

两个子图以 `commit=False` 执行，不再各自占用会话或保存助手消息；沿用父run_id、预算与取消信号。一次提问只保存一条用户消息及一条最终助手消息。子图进度带前缀，最终数字不经过模型二次改写。统一问答路径关闭旧的统计成功后提前返回逻辑。

候选优先级：明确完整文件名或《文件名主体》 → 当前发送附件/粘贴数据 → 已确认追问来源 → 当前允许的文件库及会话来源。所有Sheet都纳入候选，按12个一批评估；只有一个合格且无不确定候选才自动选择。前端最多展示12个选项，服务器保留完整紧凑候选，其他候选仍可按文件名指定。明确指定的文件不可用时，不替换为其他文件。

目录首次读取最多8条样本推断字段，仅用于发现，不用于统计。绑定后读取完整结构化记录并校验限制。没有进行Top K片段求和，也没有自动拼表。

## 3. 来源、版本与一致性

表格SQLite升级为v2，新增来源、分析会话与待清理记录。datasets增加source_id，document_id对附件/粘贴可空；旧记录回填library映射，保留原dataset/Sheet/版本/结果ID。DDL迁移显式开启事务，失败回滚；有旧数据时先自动生成 `tables.before-unified.sqlite`。

上传前登记uploading状态，异常写入可清理；未发送附件不出现在其他问题的候选。待发附件过期24小时及清理失败任务在启动时回收/重试。已发送附件默认保留到会话删除。普通撤回不能删除被历史结果引用的源；“移除上下文”和“明确删除源数据”是独立接口，前者解除后续绑定、保留历史，后者先使来源不可读，再幂等清理文件、结构化行和结果。

主要接口：

| 接口 | 用途 |
|---|---|
| `GET/POST /api/conversations/{id}/attachments` | 待发附件及上传 |
| `DELETE .../attachments/{source_id}` | 撤回未引用附件 |
| `POST .../{source_id}/remove-context` | 解除后续分析绑定，保留历史来源 |
| `DELETE .../{source_id}/source-data` | 明确删除数据并使历史来源不可用 |
| `POST .../{source_id}/save-library` | 显式另存公共文件库，重复请求复用既有文档 |
| `/api/chat`、`/api/chat/stream` | 增加attachment_ids/data_blocks/clarification_response/timezone |

当前聊天界面提供待发附件撤回、候选选择、来源查看和另存文件库；已发送来源的上下文移除/物理删除提供独立API，不混入待发附件的“×”动作。

来源访问、计算、发布、历史源行和删除均核对会话归属与文档范围。来源指纹防止静默使用更新文件；会话删除/取消后不能复活数据。已提交消息是读取计算结果的门槛。JSON消息与SQLite仍无跨存储原子事务；助手消息已保存但运行登记失败时标为needs_reconciliation，不发送成功done。

占比追溯采用共享分母引用，不为每个分组重复序列化全量分母。旧格式分母仍可读取，源行用数据库分页获取。

最终浏览器真实模型验收：

1. 直接新建聊天提问多指标：自动找表并得到1100/183.33/300/100。
2. 聊天上传Excel并提问：统计一致；来源面板显示6条Excel原始行，默认仅当前会话；显式另存文件库成功。

4. 文件库有两份相同字段报表：先展示两个候选，不自动合并；点击确认后合计1100。
5. 直接粘贴其他业务列（客户编号/地区/金额）：合计30、平均15；源行保留001/002及12.50/17.50。

浏览器使用CUA内置浏览器及其Playwright能力，当前未提供单独Browser插件。已检查相关页面无console error/warn；未开展所有屏幕尺寸的响应式验收。

### 性能抽样

合成CSV：50000行、5列、2000组。测量包含全量读取、SQLite发布、Decimal分组/占比计算和结果存储，共11.43秒；tracemalloc的Python分配峰值152.98MiB；结果JSON 988383字节，仅一个共享分母。此测量不包含LLM网络、完整进程RSS或200万单元格，不能作为完整上限性能保证。取消/删除/预算行为另由自动化测试核对。

### 验收发现并修复的问题

- LangGraph返回的新字段需登记到State，否则已展开的统计问题会被丢弃。
- 不能用文件名主体“销售”匹配“销售额”而绕过真实候选歧义。
- 追问必须把已确认分析传入表格需求提取、规划、修复和覆盖检查；只传给最外层路由会导致重复询问或把“口径不变”当新任务。
- 覆盖检查必须收到与任务理解完全相同的请求时间，防止跨年时错误否决“去年”。
- 删除/目录更新需合并最新来源状态，避免缓存写回把已删除来源重新变为可用。
- 从上下文移除附件需同步解除会话绑定，历史来源仍能读取。
- QA向量化失败时，统一功能开启且表格已成功解析可保留原文件；上传结果明确“表格可分析”，不伪造indexed状态。

## 5. 启用、回退与备份

本地 `backend/.env` 开启：

```dotenv
CHAT_RUNTIME=langgraph
TABLE_AGENT_ENABLED=true
UNIFIED_CHAT_ENABLED=true
```

默认统一预算12次模型调用/12次工具调用/180秒。默认每次5附件、单文件MAX_UPLOAD_MB（30MB）、合计100MB；粘贴最多3块/20万字符。对应配置已加入 `.env.example`。复杂语义任务需真实模型，mock只用于有限流程演示；真实模型失败不会偷偷降级mock。

重启后端并刷新前端即可使用。此次验收服务使用独立端口和数据，验收结束关闭；没有替换用户原来运行的后端进程，因此原进程需重新启动才能加载新代码和配置。

回退：将UNIFIED_CHAT_ENABLED设为false并重启，恢复原双模式；不删除新数据。若需要还原旧软件及数据库，先停后端，使用成套备份恢复源码、业务JSON、SQLite及原文件，不把新版本写入的数据库交给不理解该结构的旧软件。

实施前备份：`/private/tmp/rag-agent-unified-backup-20261018`，包含业务JSON、Agent库和表格库的在线备份、原文件、源码及环境配置。备份包含敏感配置，仅存本机受限目录，不加入仓库。隔离原始验收目录：`/private/tmp/rag-agent-unified-validation`；性能目录：`/private/tmp/rag-agent-unified-benchmark`。可复核的合成结果与截图另存本开发文档的验收证据目录。

## 6. 本期边界

- 自动找数据仅限允许的文件库及本会话附件/粘贴，不访问任意本地文件、数据库或互联网。
- 每项计算绑定单一文件/Sheet/版本；跨表JOIN/拼接、图表、导出、预测、同比、任意代码/SQL、复杂分段返点执行不在本期支持范围。
- PDF、图片、扫描件和复杂多层表头不作为本期结构化分析来源。Excel使用已有缓存值，不运行公式。
- 不自动进行单位换算、清洗、去重或删除疑似汇总行；会影响数值时需明确口径。
- 单后端进程及小规模本地JSON存储定位保持；没有新增跨存储事务、自动运行恢复、后台常驻过期清理服务或多租户认证系统。
- 实际使用效果仍取决于所配模型；本次真实模型验证是抽样验收，不能保证任意自然语言请求一次完成。
