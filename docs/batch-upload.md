# 文件与文件夹批量上传

文件库点击「上传」，在同一弹窗内多选文件或选择文件夹。普通多文件也可拖入上传区。文件夹包含所有子目录，不创建服务器文件夹树。

## 文件结构

```text
frontend/src/
  components/upload/
    uploadQueue.ts       文件类型、校验、来源路径和队列标识
    UploadProvider.tsx   路由外层队列、串行执行、停止和重试
    UploadDialog.tsx     原生 dialog、选择入口、清单、进度和结果
  api/documents.ts       XHR 传输进度及上传结果
  styles/upload.css     弹窗、清单、进度及移动端样式
  pages/DocumentsPage.tsx  文件库入口、批次结束后刷新及路径搜索
  pages/UploadPage.tsx     复用相同弹窗和队列
backend/app/
  routers/documents.py          可选 source_relative_path 表单参数
  services/document_pipeline.py 来源路径保存为文档元数据
  utils/file_utils.py           相对路径校验
frontend/tests/uploadQueue.test.ts
backend/tests/test_document_uploads.py
```

旧的单文件 FileUploader 及仅供它使用的样式已移除。App 内的 UploadProvider 位于 Routes 外层，因此切换站内页面不会丢失队列；状态保存在内存中。

## 状态与处理规则

`等待上传 → 上传中（实际传输百分比）→ 正在解析入库 → 已入库 / 失败 / 待核对`。

- 使用现有单文件接口，串行完成每个文件的传输和解析。仅收到 indexed 响应才显示已入库。
- 整批进度按已处理文件数统计，区分成功、失败、跳过和待核对；解析阶段不模拟百分比。
- 同一清单按相对路径、大小和修改时间过滤重复添加。不同子目录的同名文件分别保留；跨批次内容查重未加入。
- 支持 XLSX、CSV、PDF、DOCX；单文件沿用前端 30 MB 限制。后端仍使用现有 MAX_UPLOAD_MB 配置。
- 不支持格式、空文件、超限文件、系统文件和 Office 临时文件保留跳过原因。
- 上传前可移除、清空。仅剩一个待上传文件时保留自定义文件名功能。
- 失败不阻断后续文件。重试按钮仅重试确定失败的项。
- 网络中断、无法读取响应或网关错误会标为待核对，避免自动重传；先进入文件库确认结果。
- 停止后续上传会等待当前文件处理结束，剩余文件保持等待，之后可以继续。
- 未在上传时，每次打开弹窗均为新清单，不显示上次文件、结果和提示。当前窗口内仍可查看结果、重试失败项或继续上传。
- 上传中收起窗口后，右下角入口可恢复当前任务；处理结束后该入口消失，再次打开为新清单。刷新页面或关闭浏览器会丢失队列，已入库文档不会因此删除。
- 取消系统文件或文件夹选择时保留上传弹窗和已有清单；弹窗仅响应自身的 cancel 事件，避免内部文件输入控件的取消事件触发收起。
- 来源路径只作显示元数据，拒绝绝对路径和父目录等无效片段，不用它构建服务器文件存储路径。
- 已移除权限等级选项和检索过滤。新上传不再保存该字段；旧文档中的历史字段保留但不参与筛选，无需迁移或重新上传。

## 验证

- 前端：在 frontend 目录执行 `pnpm build`、`pnpm test:upload`。后者使用 Node 原生 TypeScript 去类型能力，Node 需支持 `--experimental-strip-types` 和全局 File。
- 后端：在 backend 目录执行 `../.venv/bin/python -m unittest discover -s tests -v`。
- 前端 4 项队列测试和后端 15 项测试通过，生产构建包含 TypeScript 检查；冒烟脚本通过。回归包含历史等级字段不影响检索、Sheet 筛选保持有效、自定义存储目录下的删除清理及文件占用后重试。
- 使用现有 Edge 和 Playwright，在 1440×1000、390×844 下验证了 8 组交互：目录选择与过滤、真实入库、限速传输进度、解析及停止恢复、失败重试、网络待核对、多文件拖拽及改名、移动布局及键盘操作。
- 页面身份、非空页面、框架错误遮罩、控制台与页面异常、截图及交互状态检查通过。
- 新清单行为另通过 9 组桌面/移动浏览器回归：未提交、跳过、成功、失败及停止后重新打开均清空，进行中恢复与系统选择取消保留当前任务；独立上传页行为一致。
- 浏览器验证使用 /tmp 中的独立数据与 mock embedding；未使用现有文件库数据或真实向量服务。Browser 插件未提供，使用已有 Playwright，未安装依赖。
- 未验证 Safari / Firefox、真实远程向量服务、大规模长期导入。项目未配置独立 lint 命令。

## 文件库管理

- 复选框始终显示，支持单选、多选、全选当前搜索结果。列表上方固定工具行显示总数和已选数量；选中后显示「取消选择」「删除所选」，表格位置及列宽保持不变。改变搜索或取消选择会清空勾选。
- 点击「删除所选」展示文件数量和目标摘要，确认后串行复用单文件删除接口。删除中显示处理数量并禁用重复提交。
- 成功项从列表移除，关联预览关闭；失败项显示具体原因并保持勾选，可重试。单文件删除位于行末「更多操作」菜单，点击外部或按 Escape 可关闭菜单。
- 后端按配置的存储目录删除原文件，同时清理文档、Sheet、Chunk 和向量记录；原文件删除失败时保留文档及索引以便重试。
- 本机隔离文件库的 7 组 Edge 浏览器检查通过，覆盖确认取消、筛选全选、串行处理、部分失败重试、原文件与索引清理、单文件删除、桌面及移动操作。

## 后续扩展边界

刷新后恢复队列、关闭浏览器后继续、解析的具体阶段百分比，以及跨批次内容查重需要额外任务或持久化机制，本次没有引入。拖入目录会提示改用「选择文件夹」。
