# 聊天正文实时流式输出

`POST /api/chat/stream` 使用 SSE，正常事件顺序为 `sources` → 一个或多个 `delta` → `done`。

- 检索、查询规划和证据门禁在正文生成前完成，因此这些步骤仍会影响首段正文等待时间。
- 模型分支每收到一个非空片段，立即发送 `delta.text`，同时积累全文供最终校验。
- `delta` 是待校验草稿，可能含有最终校验会移除或否决的内容。
- 生成结束后执行答案校验。`done.answer` 是最终结果，前端现有 `onDone` 用它替换草稿，历史也只保存该结果。
- 不再额外把完整答案追加为 `delta`，避免重复显示。
- 确定性表格结果、证据不足提示、澄清问题和空模型结果沿用一次完整正文的处理。
- 模型中断时，已发送片段保留在前端，接口发送 `error`，不发送 `done`，不保存未完成的助手草稿。

实现仅调整 `backend/app/services/chat_service.py` 的模型片段转发，复用前端已有 SSE 读取、增量追加和最终结果替换逻辑。

验证覆盖首片段早于模型结束及答案校验、正常正文无重复、校验否决或净化、证据门禁、确定性结果、澄清、空结果和模型中断。测试使用桩模型与模拟存储，不调用外部 API 或写入真实会话。

验证结果（2026-10-15）：新增 8 项流式回归通过，当前后端全套 40 项测试通过，答案质量自检、前端生产构建和差异空白检查通过。未进行真实模型 API 或浏览器端到端实测，未重启运行中服务；未启用自动重载的后端需重启后生效。
